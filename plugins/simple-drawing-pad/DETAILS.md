# Simple Drawing Pad: details

The [README](README.md) is one page. This file has the rest: every file the plugin writes, the browser board in detail, the Microsoft Store version of the Claude app, updates from older versions, the `/draw` alias and what changed in each release.

## What it runs and stores

The program and everything it saves are in one folder under your user profile, `C:\Users\<you>\simple-drawing-pad` (below: the folder): the program in `app\`, your last drawing in `drawings\`, the shortcut setting and the plugin's state files next to them. Outside it are the Startup shortcut, the entry for Windows Settings > Apps in the registry and the build output in the plugin's `app\bin\`. A folder directly under the user profile is the same folder for every program that runs as you, including the Microsoft Store version of the Claude app; Explorer shows it, and OneDrive does not sync it.

- `/simple-drawing-pad:install` and `/simple-drawing-pad:uninstall` only ask Claude to run `install.ps1 -Autostart` or `install.ps1 -Uninstall` (which runs `uninstall.ps1`); Claude Code asks you to approve the command first.
- `install.ps1` builds `SimpleDrawingPad.exe` from the included source (`app/SimpleDrawingPad.cs`) with the Windows C# compiler `csc.exe` into `app\bin\` inside the plugin folder (the build script also draws the pencil icon, the same drawing as the tray icon, into the program file, so Task Manager shows it), copies it to the folder's `app\` and starts it in the notification area. It stops a running helper first; if the build or a later install step fails, it starts the installed one again.
- Next to the program, in `app\`, `install.ps1` keeps a copy of `uninstall.ps1` and writes `source.sha256` (a hash of the program's source and its build and uninstall scripts) and `version.txt` (the plugin version), so the check can tell when a plugin update brings a newer program, and an older copy of the plugin never asks to put its older program back.
- With `-Autostart` it creates the shortcut `Simple Drawing Pad.lnk` in your Startup folder (`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`, `shell:startup` in Explorer), which starts `app\SimpleDrawingPad.exe --tray` at logon. This is the usual per-user autostart: Task Manager lists it under Startup apps, and you can delete the shortcut in Explorer. It works from the Microsoft Store version of the Claude app too (below).
- The helper runs once per Windows sign-in: at start it takes a named mutex, `Local\SimpleDrawingPad.Tray`, and a second `--tray` start that finds it taken ends at once, without an icon or a message and without writing `helper.txt`.
- It lists the program in Windows Settings > Apps with a per-user entry `simple-drawing-pad` under `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall` (name, version, icon, folder, size). Windows shows the entry when the install ran from `claude` in a terminal or from the Claude app installed from claude.ai; from the Microsoft Store version of the Claude app the entry stays inside that app's sandbox and does not appear. Where it appears, its Uninstall button runs the copy of `uninstall.ps1` in `app\`: the same steps as `/simple-drawing-pad:uninstall`, so it also works after the plugin is removed from Claude, and a small message window tells you the result. Without Claude and without the entry, the same copy does the same when you run it with PowerShell: `powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\<you>\simple-drawing-pad\app\uninstall.ps1"`.
- The last drawing and the plugin's state are kept in the folder, on this computer only:
  - `drawings\latest.png`: the drawing you last copied with Enter (or by closing the window), overwritten by the next one. `drawings\status.txt` is the result of the last drawing session: line 1 `copied`, `cancelled` or `empty`, line 2 the path of `latest.png` (empty otherwise), line 3 the time. Esc writes only `status.txt` and leaves `latest.png` as it was. The copy that Shift+Enter saves where you choose is yours; the helper never touches it again.
  - `shortcut.txt`: the keyboard shortcut, once you changed it from the tray menu.
  - `helper.txt`: written by the helper each time it registers its shortcut (whether it could, which shortcut, its process id, the time), deleted when you exit it from the tray menu. A helper stopped another way leaves it behind; the check then ignores it.
  - `notice.txt`: which session-start notice was already shown, so each one appears only once.
  - `no-reminder.txt`: written when the helper is removed; it tells a 0.5.0 copy of the plugin, which may still be in another Claude app, not to remind you. The next install deletes it.
- `app/status.ps1` reads whether the program is installed, whether its helper is running, `helper.txt`, the Startup shortcut, the Settings entry (as Windows sees it, through WMI), `source.sha256` and `version.txt`; on its own it changes nothing.
- **Session start (hook):** at the start of each new Claude Code session, `hooks/hooks.json` runs `powershell ... status.ps1 -SessionStart`. On Windows it prints nothing when all is well. Otherwise it shows you a notice once per computer and problem (the first one is the one-time question whether to install the helper) and remembers that in `notice.txt` (creating the folder for it when it does not exist yet), and it tells Claude the state so Claude can help when you ask (it asks before installing anything). On macOS and Linux there is no `powershell` command, so it does nothing. A plugin update can change this script; the helper program itself changes only when you run `/simple-drawing-pad:install`.
- Each copied drawing is put on the clipboard, and a Windows notification says so ("paste it with Ctrl+V"). If another program keeps the clipboard busy, the drawing is only saved, and the notification says that instead.
- To pick up a drawing by itself in Claude Code, Claude runs a small PowerShell loop in the background that checks `drawings\status.txt` every 2 seconds, for up to 30 minutes, and then opens the PNG it names. It only reads that folder.
- `-Uninstall` (and the Uninstall button in Settings, where Windows shows the entry) stops the helper and removes `app\` with the program, `uninstall.ps1`, `source.sha256` and `version.txt`, removes `helper.txt`, the Startup shortcut and the Settings entry, and writes `notice.txt` and `no-reminder.txt` so the plugin does not ask about the helper again on this computer (the next install deletes them). `drawings\` and `shortcut.txt` are kept, and so is the build output in the plugin's `app\bin\` folder.

## The browser board

`skills/draw/assets/simple-drawing-pad.html` loads nothing from the network and stores nothing. Press and hold while moving to draw (on a trackpad: click and drag, or double-tap and drag); a thicker pen is easier. With a pen, a resting palm does not draw. Undo is Ctrl+Z, redo Ctrl+Y or Ctrl+Shift+Z (⌘Z and ⇧⌘Z on a Mac). Before a reload or closing the tab would lose a drawing, the browser asks first.

- **Copy** puts a PNG of the whole drawing, also ink outside the current window, on the clipboard through the browser; you paste it into the chat. **Save picture** saves the same PNG through the browser's normal download (usually in Downloads). Where the browser blocks either one, the board shows the picture instead, to long-press (or right-click) and copy or save, or to take a screenshot of.
- **Claude Code on macOS or Linux** (or Windows without the helper): Claude opens the board in its browser pane, or in your default browser. In the pane, say "done" when you finish and Claude takes a screenshot of it. In a browser, click Copy and paste into the chat, or drag the saved PNG from your Downloads folder into the chat.
- **Phone, claude.ai, cloud sessions, Remote Control:** Claude publishes the board as your private artifact; on a phone it also offers, in the same message, to draw on paper and send a photo with the + or paperclip button, the quickest way there. On the board: draw with your finger or mouse, tap Copy and paste the drawing into the chat. If Copy is blocked there, take a screenshot (iPhone: side + volume up; Android: power + volume down; Windows: Win+Shift+S) and attach it; on a phone, take it before you close the board. Claude cannot see the board itself, so without Send to Claude saying "done" is not enough: paste or attach the drawing.
- **Send to Claude.** When Claude Code publishes the board as an artifact, it declares one capability of Claude's artifact viewer for it, `assets`. For you, the artifact's owner, the board then shows Send to Claude; everywhere else (a plain browser, Claude Code's browser pane, a chat artifact on claude.ai, a saved file) the button stays hidden and the board works as above. A tap hands the PNG of the whole drawing to the viewer, which stores it with your private artifact; the button then reads Sent, and the board asks you to write "done" in the chat. Claude then lists the files stored with the artifact and reads the newest picture. The same drawing is not sent twice: until it changes, another tap stores nothing and says it was already sent. If the upload fails, the board says so and asks for Copy or a screenshot. The picture is deleted with the artifact.

## Claude from the Microsoft Store

The Store version of the Claude app runs the plugin's commands in a sandbox. Registry entries and new AppData folders written from inside it belong to the app alone: Windows does not start from them, Windows Settings > Apps does not list them, and Explorer does not show them. That is why 0.8.0 moved everything to `C:\Users\<you>\simple-drawing-pad`, a folder every program on your computer sees, and starts the helper by a shortcut in your Startup folder, which is real from inside the sandbox too. Tested on Windows 11 with the Store app: after a restart Windows started the helper from that shortcut, before Claude was opened. Settings > Apps does not list the helper there; remove it with `/simple-drawing-pad:uninstall`. The Claude app from claude.ai (EXE) and `claude` in a terminal have no sandbox; they use the same folder and shortcut.

## Updates from older versions

- **0.5.1 to 0.7.9** kept the program in `%LOCALAPPDATA%\Programs\simple-drawing-pad`, the drawings and the state files in `%LOCALAPPDATA%\simple-drawing-pad`, the shortcut setting in `%APPDATA%\simple-drawing-pad\shortcut.txt`, and started with Windows by a value `simple-drawing-pad` under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. The check reports such a program as `update-available`, with a notice that says what changed. `install.ps1` then stops a helper running from the old folder, removes the old program files and the old Run value, copies the shortcut setting when the new file does not exist (the helper also reads the old file while the new one is missing), and removes the old state files (`helper.txt`, `notice.txt`, `no-reminder.txt`) and the old folders under `%LOCALAPPDATA%` once they are empty. `uninstall.ps1` removes the old Run value, the old program files and the old `helper.txt` too. Drawings left in `%LOCALAPPDATA%\simple-drawing-pad\drawings` and the setting in `%APPDATA%\simple-drawing-pad` are not touched.
- **Before 0.5.1** drawings were saved in `Pictures\simple-drawing-pad`, which OneDrive may sync between computers; they stay there untouched.

## The `/draw` alias

If you prefer typing `/draw`, add a command of your own: commands from a plugin always carry the plugin's name, so the plugin cannot register `/draw` itself. Create `C:\Users\<you>\.claude\commands\draw.md` (on other systems `~/.claude/commands/draw.md`) with:

```markdown
---
description: Simple Drawing Pad (alias for /simple-drawing-pad:draw)
---
Run the skill `simple-drawing-pad:draw`. Arguments: $ARGUMENTS
```

## What changed since 0.7.9

0.7.9 is the version in the Claude directory. The versions after it, newest first.

- **0.9.9: the mouse draws in tablet mode too.** A Wintab driver can stay installed with no tablet attached (an old driver left behind); the board then opened in tablet mode and ignored the mouse, so nothing could be drawn. Now the mouse draws while the pen is away from the tablet (its own mouse messages are skipped, so a pen stroke is not drawn twice), and the cursor is kept on the sheet only while the pen is near, so the mouse can reach the toolbar. Under the width buttons 1-5 the bar shows a short line as thick as the line each draws; the chosen width's line is in the pen colour (grey with the eraser on), the others pale. Without a keyboard: the Start menu tile and the Store's Open button now open the board (before, they only started the notification-area helper, and nothing seemed to happen), and one click or tap on the tray icon opens it too; the Store package's startup task at sign-in still starts the helper quietly.
- **0.9.8: a Store package.** The helper started without arguments is now the notification-area helper, as `--tray` always was; `--board` opens the drawing window at once. This lets the Microsoft Store package and its startup task start it without arguments. The Store package is built from the same source by `store/build-msix.ps1`; Microsoft signs it, which also satisfies Smart App Control. The README, the install command and the draw skill say what to do when Windows blocks an unsigned helper: use the browser board.
- **0.9.7: a smaller trust surface.** The check no longer walks up the parent processes to name the Store version of the Claude app; it only reads whether Windows lists the program in Settings > Apps. The Settings > Apps entry no longer starts a hidden PowerShell window. Two sentences are more exact: `-ExecutionPolicy Bypass` applies to the whole command it is given to, and closing the pen window also copies the drawing, as Enter does. The helper program is unchanged, so no update notice.
- **0.9.6: less.** This release removes, so that a person can read the plugin's files in minutes and nothing happens without their knowledge. Gone are:
  - The drawing history. The helper keeps one file, `drawings\latest.png`, overwritten each time: no time-stamped files, no `cancelled\` folder (Esc writes only `status.txt`), no `latest.txt`. The copy you save with Shift+Enter is the only way to keep a drawing.
  - The AltGr warning in the shortcut dialog. The helper calls no keyboard-layout API; if the shortcut collides with a letter on your keyboard layout, change it from the tray menu.
  - Every trace of the 0.3.0 name drawing-board in the helper, the scripts and the docs.
  - The stub that 0.9.0 left in the old 0.7.9 program folder, the second `helper.txt` the helper wrote for it, and what the check and the uninstall did about them. An update from 0.5.1 to 0.7.9 still stops the old helper, removes the old program, Run value and state files and copies the shortcut setting; old drawings stay where they are.
  - On the board, the comment that told Claude about a sent drawing, and Tell Claude. Send to Claude only stores the picture with your private artifact (the `assets` capability); you then write "done" in the chat and Claude reads it.
  - In the draw skill, everything but three cases: the pen window at a Windows PC, the browser board, a photo of a paper sketch.
  - In the READMEs, everything but one page each; the details are in this file.
  - In `tests/`, the steps that tried removed things; the headless check now covers `latest.png`, `status.txt` and Esc.
  - In the listing, the description is shorter: the key lines, the sentence that nothing is collected and nothing goes to third parties, and one sentence that a short local check runs at each session start. The full privacy text, including Send to Claude, is in the READMEs.
  - The privacy sentence in the listing and in both READMEs covers the board too: on your PC everything stays local with no network; on the board that Claude publishes as your private artifact, Send to Claude uploads the drawing there, and only when you tap it. The old sentence, "Local only, no network, collects nothing", was written for the Windows helper alone.
  - The draw skill also starts when your message is only the word draw or sketch, and both READMEs give three example prompts.
  - The session-start hook names the plugin folder the way the directory's checklist asks, `-File "${CLAUDE_PLUGIN_ROOT}/app/status.ps1"`, instead of an inline `-Command` program. The question before the install, and what Claude says when it offers the install, now also say in one sentence that the shortcut works in every program and can be changed from the pencil icon's menu.

  0.9.6 changes the helper program, so on a computer with an older helper the plugin's check reports `update-available` once and asks you to run `/simple-drawing-pad:install`.
- **0.9.1: trademark note.** Both READMEs end with a note that the project is not affiliated with Wacom and contains no Wacom software; on Windows it uses the Wintab interface of the tablet driver you already have installed. No code changed.
- **0.9.0: Save as, phones and claude.ai, Send to Claude.** Pen window: Shift+Enter also saves a copy where you choose, and the status text on the bar names it; one helper runs at a time; a failed install step restarts the helper. The draw skill picks the path first and asks whether you are at the computer before naming a shortcut. Browser board: Copy, the picture shown where a copy or download is blocked, palm rejection, a guard against losing the drawing on reload, export of the whole drawing, a fullscreen guard, a toolbar that fits phones and narrow windows. Send to Claude on the board published by Claude Code, tested on Android in the Claude app. Listing: the description names what a sketch can be and the browser board; keywords diagram, wireframe, mockup, whiteboard and handwriting. The READMEs name the `/draw` alias. `tests/`: a headless check of the save routine with Mono (`run.sh`) and the steps that need a Windows PC (`windows.md`). The AltGr warning and the stub in the old program folder that this version added were removed again in 0.9.6.
- **0.8.0: one folder, starts with Windows from the Store app too.** The Microsoft Store version of the Claude app runs the plugin's commands in a sandbox, so the registry entries and new AppData folders that 0.7.9 wrote belonged to the app alone: the helper never started with Windows, Settings > Apps never listed it, and the drawings were invisible in Explorer and deleted with the app's data. Since 0.8.0 the program, the drawings, the shortcut setting and the plugin's state files are in one folder, `C:\Users\<you>\simple-drawing-pad`, which every program on the computer sees and OneDrive does not sync, and the helper starts with Windows by the shortcut `Simple Drawing Pad.lnk` in the Startup folder instead of a Run value; install and uninstall remove the old value. Tested on Windows 11 with the Store app: after a restart Windows started the helper before Claude was opened. An install over 0.5.1 to 0.7.9 moved the program, the drawings and the shortcut setting to the new folder (since 0.9.6 the old drawings stay where they are), and users of those versions get one notice at session start that says what changed. The check reports autostart from the shortcut, the Settings > Apps entry as Windows sees it, a program still in the old folder as an update to install, and names the Store version of the Claude app. Removal is `/simple-drawing-pad:uninstall`; Settings > Apps lists the program where Windows can see the entry. The issue form asks how Claude is installed.

Unchanged throughout: no administrator rights, nothing downloaded (the helper is built on your PC from the included source with the compiler that ships with Windows), no data collection, and the one-time question before the helper is installed. Every release is one signed commit on `main` with a tag `simple-drawing-pad--v<version>`.
